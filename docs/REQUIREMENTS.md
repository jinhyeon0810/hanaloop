# Hanaloop PCF Dashboard — Requirements

제품 단위 탄소 발자국(PCF) 측정·시각화 대시보드의 요구사항.

## 1. 개요

- **대상 제품:** CT-045 컴퓨터 화면 (단일 제품)
- **회계 범위:** Cradle-to-Gate + Transport (원소재 → 공장 가공 → 출고 운송)
- **출력 단위:** kgCO2e (총량이 1000 이상이면 t CO2e로 자동 전환)
- **시드:** 활동 30건 + 배출계수 4건이 자동 주입되어 즉시 데모 가능
- **목적:** 활동 데이터(전기·원소재·운송)를 입력·임포트하여 제품 PCF를 산정하고, 두 페르소나(실무자/경영자)에게 적합한 형태로 시각화한다.

## 2. 도메인 용어

| 용어                  | 정의                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| **PCF**               | Product Carbon Footprint. 제품 생애주기 동안의 총 CO2 등가 배출량 (kgCO2e)                 |
| **범위(scope)**       | Cradle-to-Gate + Transport — 원소재 → 공장 가공 → 출고 운송                                |
| **활동(activity)**    | 배출을 유발하는 단위 행위. 일자/유형/설명/량/단위로 구성                                   |
| **활동 유형**         | `전기` (kWh) · `원소재` (kg) · `운송` (ton-km)                                             |
| **배출계수(factor)**  | 활동량을 kgCO2e로 환산하는 곱셈 계수. 활동마다 매칭되는 단일 계수가 존재                   |
| **페르소나**          | `operator`(실무자, 데이터 입력) · `executive`(경영자, KPI 열람)                            |

계산 규칙·계수 매칭 알고리즘·에러 코드 등 도메인 계산의 단일 출처는 `.claude/skills/pcf-calculation-rules/SKILL.md`. 본 문서는 *무엇을 만드는가*에 집중한다.

## 3. 페르소나

| 페르소나      | 주 과업                                          | 화면 밀도                                  |
| ------------- | ------------------------------------------------ | ------------------------------------------ |
| `operator`    | 활동 데이터 입력(폼/Excel), 활동 목록 검토       | 높음 (표, 필터, 데이터 품질 신호)          |
| `executive`   | 현재 기간 총 배출량과 추이 한눈에 파악           | 낮음 (KPI 타일, 차트, 정적 표시)           |

**페르소나는 권한이 아니라 뷰 모드.** URL로 페르소나를 전환할 수 있다 (`?role=operator|executive`). 인증 없음 — 모든 라우트가 양 페르소나에게 접근 가능. 데이터 변경도 누구나 가능 (실 배포 시 RBAC 필요).

페르소나가 결정하는 것:
- **기본 랜딩 화면** — `/` 직접 접근 시 executive 뷰 우선 (데모 첫인상)
- **네비게이션 항목 노출** — operator만 "활동 추가", "Excel 임포트" 메뉴 표시
- **대시보드의 일부 영역** — operator만 데이터 품질 섹션 노출 (§4.3 참조)
- **표·KPI의 인터랙션** — operator는 KPI 클릭 가능, executive는 정적

## 4. 기능 요구사항

### 4.1 활동 입력 — 폼

- 경로: `/activities/new` (operator UI에서만 메뉴 노출, URL 직접 접근은 누구나 가능)
- 필드: 일자, 활동 유형, 설명, 량, 단위
- 입력 제약:
  - 활동 유형: 드롭다운 (전기/원소재/운송)
  - 설명: 드롭다운 (선택한 활동 유형에 매칭되는 계수 항목만 노출 — 예: 전기 → 한국전력)
  - 단위: 드롭다운 (선택한 활동 유형의 기본 단위로 자동 고정 — 전기=kWh, 원소재=kg, 운송=ton-km)
  - 일자: 날짜 피커
  - 량: 양수만 허용 (0·음수·비숫자는 인라인 에러 즉시 표시)
- 잘못된 입력은 인라인으로 즉시 표시되고 저장되지 않는다
- 저장 후 활동 목록(`/activities`)으로 이동, 토스트로 "1건 추가됨" 알림

### 4.2 활동 임포트 — Excel/CSV

- 경로: `/activities/import` (operator UI에서만 메뉴 노출)
- 허용 포맷: `.xlsx`, `.csv` (UTF-8, 10MB 이하)
- **제공된 시드 Excel 그대로 임포트 가능** — 별도 가공 없이 직접 적재
- 한글 헤더 5컬럼 인식: `일자`, `활동 유형`, `설명`, `량`, `단위`
- 부분 성공 정책: 행 단위 검증 실패는 전체 파일을 막지 않음. 결과 화면에 Accepted/Duplicates/Rejected 3구역 표시
- 거부 행은 CSV로 export 가능 (원본 값 + 한국어 에러 메시지)
- 동일 파일을 재업로드하면 0건 신규로 표시되고, 같은 행이 다른 파일로 들어와도 중복으로 인식한다
- 같은 날짜·항목·다른 수량은 **별개 활동으로 인정** (예: 5월에 두 번 발생 케이스)

### 4.3 대시보드

- 경로: `/` (기본 랜딩 화면)
- 페르소나 무관 공통:
  - 상단 KPI 타일 4개:
    - 선택 기간 총 배출량 (단위 자동: < 1000 kgCO2e, ≥ 1000 t CO2e)
    - YTD 누적 (t CO2e, 2025-01-01부터 가장 최근 활동까지)
    - 활동 건수 (선택 기간)
    - 가장 큰 기여 활동 유형 (예: "전기 — 전체의 62%")
  - 기간 선택자: **2025 Q1 / Q2 / Q3 / YTD** (드롭다운 한 개)
  - 차트 1개: 활동 유형별 누적 막대 (가로형, 한글 라벨)
- **executive 뷰:** 위 공통만 노출. KPI 타일은 정적 (클릭 불가), 단위는 t CO2e 강조
- **operator 뷰 추가 영역 (대시보드 하단):**
  - **데이터 품질 배지** — 계수 매칭 실패 활동 건수 표시. 클릭 시 `/activities?filter=unmatched` 이동
  - **최근 임포트 요약** — 가장 최근 임포트의 Accepted / Duplicates / Rejected 카운트
  - KPI 타일 클릭 가능 → 해당 필터로 활동 목록 이동

### 4.4 활동 목록

- 경로: `/activities` (양 페르소나 접근 가능, operator UI는 좌측 메뉴에 노출)
- 표 컬럼: 일자(정렬 기본), 활동 유형, 설명, 량 + 단위, 매칭된 계수 + 출처(짧게), 계산된 kgCO2e
- 필터: 기간(분기 또는 YTD), 활동 유형, 매칭 실패만 보기 토글
- 같은 날짜·항목·다른 수량 건은 **합산하지 않고 두 행 그대로 표시**
- 행 단위 에러 상태: 매칭 실패 시 행에 경고 아이콘 + 호버 시 메시지
- 수정·삭제 버튼 없음

### 4.5 계수 목록

- 경로: `/factors` (페르소나 무관 동일 화면, 편집 버튼 없음)
- 표: 활동 유형, sub_category, 값, 단위, 유효 기간, 출처(source)
- 필터: 활동 유형
- 목적: "대시보드의 숫자가 어떤 계수에서 나왔는지" 감사 추적

## 5. 비기능 요구사항

### 5.1 성능
- 대시보드 초기 로드 LCP ≤ 2.5s (시드 데이터 30건 기준)
- CLS ≤ 0.1 (모든 화면)
- Excel 임포트: 30~1000행 처리 ≤ 5s (서버 측)

### 5.2 안정성·접근성
- 에러가 발생해도 해당 영역만 에러 상태로 표시되고 전체 화면은 유지된다
- 데이터 로딩 중에는 최종 레이아웃과 동일한 형태의 placeholder가 표시된다 (회전 스피너 금지)
- 새로고침에도 페르소나·필터·기간 선택이 유지된다
- 키보드만으로 모든 인터랙션 가능, 시각적 focus 상태 명시
- 색만으로 의미 전달 금지 (방향·라벨·아이콘 병기)

### 5.3 에러 처리
- 도메인 에러(계수 없음, 수량 무효, 단위 불일치)의 카탈로그는 `pcf-calculation-rules` SKILL이 단일 출처
- 임포트 레이어 에러(파일 포맷·인코딩·필수 컬럼 누락 등)는 별도 등록
- 사용자 노출 메시지는 한국어, Excel 임포트의 거부 행은 행 번호와 컬럼 명을 포함한다
- 네트워크 실패가 화면을 화이트스크린으로 만들지 않고 에러 상태로 표시된다
